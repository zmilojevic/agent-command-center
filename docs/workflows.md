# Workflow designer

Visual editor for Claude Code saved workflows: the scripts the `Workflow` tool runs by name. Project scope is
`<project root>/.claude/workflows/<name>.js`, user scope is `~/.claude/workflows/<name>.js`; the file's base name equals
`meta.name`. The designer edits a constrained graph and generates the script from it; the graph is embedded in the
script, so it can be reopened. Scripts written by hand or by Claude open as a read-only outline plus code.

## Script API the generator targets (summary)

The body is plain JavaScript run as an async function body (top-level `await` and `return` are allowed). It must begin
with `export const meta = {...}`, a pure literal: `name`, `description`, optional `whenToUse`, `phases: [{title, detail?}]`.
Hooks: `agent(prompt, {label, phase, schema, model, effort, isolation: 'worktree', agentType})` (string result, or the
validated object with `schema`; `null` when skipped or failed), `parallel(thunks)` (barrier, failed thunk → `null`, never
rejects), `pipeline(items, ...stages)` (each stage gets `(prevResult, originalItem, index)`, no barrier between stages, a
throwing stage drops that item to `null`), `phase(title)`, `log(msg)`, `args` (the run's input, verbatim).
`Date.now()`, `Math.random()` and argless `new Date()` throw; no filesystem or Node APIs. Schemas need
`{type:'object', properties, required}` at the root with `required ⊆ properties`.
`agentType` resolves in the same registry as the Agent tool: project `.claude/agents`, user `~/.claude/agents`, plugin
agents, built-ins (`general-purpose`, `Explore`, `Plan`, …). Project agents only resolve when the run's session is in that
project.

## Graph model (`src/shared/workflow.ts`)

```ts
type WfFieldType = 'string' | 'number' | 'boolean' | 'string[]'
interface WfField { name: string; type: WfFieldType; description?: string }

interface WfAgentStep {
  kind: 'agent'
  id: string            // slug [a-z][a-z0-9_]*, unique in the graph; used in {{refs}} and as the result key
  label: string
  prompt: string
  agentType?: string    // absent = default workflow subagent
  model?: string        // absent = inherit (agent definition, else session)
  effort?: 'low' | 'medium' | 'high' | 'xhigh' | 'max'
  worktree?: boolean
  output: 'text' | WfField[]   // fields → JSON schema, every field required
}

interface WfForEachStep {
  kind: 'forEach'
  id: string
  label: string
  over: string          // reference without braces: 'args', 'args.<field>', '<stepId>', '<stepId>.<field>'
  stages: WfAgentStep[] // pipeline stages (≥ 1); stage ids are unique graph-wide too
  verify?: { votes: number; prompt: string }  // adversarial check after the last stage; keeps majority-not-refuted items
}

type WfStep = WfAgentStep | WfForEachStep
interface WfPhase { id: string; title: string; detail?: string; steps: WfStep[] }

interface WfGraph {
  version: 1
  name: string          // [a-z0-9][a-z0-9-]*, = file name
  description: string
  whenToUse?: string
  argsHint?: string     // free text shown in the Run dialog ("a path", "JSON {topic, depth}")
  phases: WfPhase[]
  output: string[]      // ids of top-level steps returned by the workflow; empty = all top-level steps
  layout?: Record<string, unknown>  // reserved for the UI, ignored by the generator
}
```

Semantics: phases run in order; steps inside a phase run in parallel (one `parallel()` barrier per phase; a phase with
one step awaits it directly). A step can reference only steps of *earlier* phases, plus `args`.

### Prompt references

`{{args}}`, `{{args.x}}`, `{{<stepId>}}`, `{{<stepId>.<field>}}` anywhere in a prompt. Inside a forEach stage also
`{{item}}`, `{{item.<field>}}` (the current element) and `{{prev}}` (the previous stage's result; for the first stage it
is the item). Anything else in `{{…}}` is a validation error. References are rendered with `fmt()` (strings verbatim,
everything else pretty JSON).

## Generated script

```js
export const meta = {
  name: 'review-changes',
  description: 'Review the diff and verify each finding',
  whenToUse: '…',                                   // omitted when empty
  phases: [{ title: 'Find', detail: '…' }, { title: 'Report' }],
}

// Generated by the Agent Command Center workflow designer. Edit it there: the designer detects hand edits
// and asks before overwriting them.
const fmt = (v) => (typeof v === 'string' ? v : JSON.stringify(v, null, 2))
const list = (v) => (Array.isArray(v) ? v : v == null ? [] : [v])
const out = {}

phase('Find')
await parallel([
  async () => { out.bugs = await agent(`Find bugs in ${fmt(args)}`, { label: 'Bugs', phase: 'Find', schema: {…} }) },
  async () => { out.perf = await agent(`…`, { label: 'Perf', phase: 'Find', agentType: 'Explore', effort: 'low' }) },
])

phase('Report')
out.verified = (await pipeline(list(out.bugs?.findings),
  (prev, item, i) => agent(`Check ${fmt(item)}`, { label: `Check ${i + 1}`, phase: 'Report' }),
  async (prev, item, i) => {
    const votes = (await parallel(Array.from({ length: 3 }, (_, v) => () =>
      agent(`<verify prompt>\n\nItem:\n${fmt(item)}\n\nResult to check:\n${fmt(prev)}\n\nTry to refute it. If unsure, set refuted to true.`,
        { label: `Verify ${i + 1}.${v + 1}`, phase: 'Report', schema: VERDICT })))).filter(Boolean)
    return votes.filter((x) => !x.refuted).length * 2 > 3 ? prev : null
  },
)).filter((x) => x != null)

return { bugs: out.bugs, perf: out.perf, verified: out.verified }

/* ccd-workflow-graph v1 <hash>
{ …graph JSON… }
*/
```

Rules:
- Options objects include only what is set (`schema` only for field outputs, `isolation: 'worktree'` only when on).
- `VERDICT` = `{type:'object', properties:{refuted:{type:'boolean'}, reason:{type:'string'}}, required:['refuted','reason']}`,
  declared once near the helpers when any step verifies.
- User text inside template literals escapes `\`, `` ` `` and `${`; references become `${fmt(<expr>)}` where `args` → `args`,
  `args.x` → `args?.x`, `s` → `out.s`, `s.f` → `out.s?.f`, `item` → `item`, `item.f` → `item?.f`, `prev` → `prev`.
- forEach stage labels are `${label} ${i + 1}` (multi-stage: the stage's own label).
- The trailing comment holds the graph JSON. `<hash>` = FNV-1a 32-bit hex of the code part (everything before the comment,
  trimmed). Loading: comment present and hash matches → editable; comment present, hash differs → editable with an
  "edited by hand" warning (saving overwrites those edits after a confirm); no comment → read-only.
- The generator never emits `Date.now`, `Math.random` or `new Date()`.

## Validation (shown in the UI, blocks Save only for errors)

Errors: bad or duplicate name/ids, empty phase title, duplicate phase titles, empty prompt, unknown or same/later-phase
reference, `{{item}}`/`{{prev}}` outside a forEach, forEach with no stages, votes < 1, empty field names or duplicates.
Warnings: user-scope workflow using a project agent; forEach `over` pointing at a text-output step (it becomes a
one-element list); phase without steps.

## Main process (`src/main/workflows.ts`)

IPC (all in `PHONE_BLOCKED`):
- `workflow:list(root)` → `WorkflowFile[]` `{name, scope, path, description, mtime, kind: 'designer' | 'edited' | 'script'}`
  for `<root>/.claude/workflows/*.js` and `~/.claude/workflows/*.js` (missing dirs = empty).
- `workflow:read(path)` → `{code, graph?, kind, meta: {name, description, whenToUse?, phases: {title, detail?}[]}}`.
  Without a graph comment `meta` is pulled out by regex (never executed). Paths outside the two workflow dirs are refused.
- `workflow:save({root, scope, graph, previousPath?, force?})` → `{ok: true, path} | {ok: false, error} | {ok: false,
  conflict: 'edited' | 'script' | 'exists'}`. Generates the code in main from the graph (same shared generator),
  `mkdir -p`, writes atomically (tmp + rename). Conflicts unless `force`: target is a hand-edited or non-designer script, or
  a different workflow already has that name. After writing, `previousPath` (a rename or scope move) is removed.
- `workflow:delete(path)` → error string or null.
- `workflow:agents(root)` → `WorkflowAgent[]` `{name, description, model?, source: 'project' | 'user' | 'other'}`: SDK
  `supportedAgents()` on a temporary idle query with `cwd = root` (same pattern as `listAllModels`, cached 60 s per root),
  sources tagged by scanning `.claude/agents/*.md` and `~/.claude/agents/*.md` (frontmatter `name:`, else the file name).

## UI

- Entry: sidebar project context menu "Workflows…" (desktop only, not the Chats section). Store `workflowsRoot: string |
  null` (project root, not persisted). While set, App renders `WorkflowsView` instead of the chat pane, right dock and tool
  strip; the TopBar stays. Opening any chat, starting a new chat, or the view's close button clears it.
- Layout: left column (list) · canvas · inspector (selected step), all inside `.main-row`.
- List: sections "Project" and "User"; rows show name, description, a muted chip `script` / `edited`. "New workflow" button.
  Below the list the agent palette (`workflow:agents`) grouped Project / User / Built-in; dragging an agent onto a phase
  column adds an agent step with that `agentType`.
- Canvas: phases as columns left to right (fixed width, horizontal scroll), small arrows between them, "+ Phase" at the end
  and an "Output" column with the returned steps. Column header: editable title, detail, menu (move left/right, delete).
  Cards: label, agent chip, model·effort chip, output chip (`text` / `N fields`), worktree icon; forEach cards show `over`,
  their stages as a mini chain and a `verify ×N` chip. Cards drag within and between columns. An SVG layer draws muted
  curves from each referenced step to the step that references it (highlighted for the selected card).
- Inspector: label, id, agent Dropdown (Default + palette entries with source as description), model Dropdown (Inherit +
  `listAllModels`), effort Dropdown (Inherit + levels), worktree switch, prompt textarea with an "Insert reference"
  Dropdown (args, earlier steps and their fields, item/prev inside forEach), output Text / Fields editor. forEach: `over`
  Dropdown, stage list (select a stage → same agent inspector), add/remove/reorder stages, verify switch with votes and
  prompt. Validation messages for the selection at the top; all of them in a footer.
- Header: name, description, scope Dropdown (Project / User), when-to-use, args hint; Save (Ctrl+S), Code (toggle a
  read-only highlighted view of the generated script), Run…, Delete…. Unsaved changes are marked; switching workflows or
  closing with unsaved changes asks.
- Run…: dialog with an args textarea (prefilled hint), "Run in a new chat" → new chat in the project root that sends
  ``Run the saved workflow `<name>` with args: <args>`` (no args → "with no args"). That message is the explicit opt-in
  the Workflow tool requires.
- Read-only scripts: phases from `meta` as empty columns, a note that the script was not made in the designer, the code
  view, and Run….
- Never native `<select>`; Dropdown everywhere. Styles in `src/renderer/src/styles/workflows.css`, muted palette.
